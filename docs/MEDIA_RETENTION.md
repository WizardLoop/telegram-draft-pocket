# Durable media ownership

The completed [Mac run 42007374615](https://github.com/WizardLoop/telegram-draft-pocket/actions/runs/42007374615), at `d02b731`, built the full app and passed all 15 Postbox byte-retention/validation cases and all 25 Core cases, including 10 media-lifecycle cases. Both held-lease cold reopen and recovery after deleting an external attachment passed. The newer SQL-first startup correction at `25a3961` still requires native execution. These results establish the tested storage lifecycles, not every media/upload scenario; see [TESTING](TESTING.md) for exact revisions and evidence.

The account's MediaBox stages immutable verified copies under `retained-draft-resources`. Generated/hash identifiers form the paths; message text and user filenames do not. Files and pin metadata are flushed before a transfer. A cross-process file lock covers preparation, the fresh Postbox owner transaction and post-commit collection. Failed preparation leaves the composer unchanged. Abandoned stages can be reclaimed only after consulting the current owner graph.

Postbox preferences contain the versioned owner graph and full interrupted-send recovery snapshots. Owners represent cards, Delete/Undo tombstones, active chat/topic drafts, prepared sends and real outgoing global message IDs. Pocket, active-state and ownership changes commit together. Autosave narrows active ownership when media is removed. Corrupt optional ownership metadata retains conservative pins without blocking ordinary text autosave or an unrelated send.

After an actual corrupt-ownership test exposed a low-level decoder assertion, Pocket decoding gained opt-in framing and container validation. It checks encoded lengths, wire types, nesting and count bounds before invoking legacy readers, including separately encoded snapshot fields. Ownership writes use the same validation before any mutation, including prepared-send recovery snapshots. Default Postbox callers keep their existing behavior. The original failing case and the added framing, container and unreadable-recovery cases passed in the `d02b731` Mac run. This does not validate every semantic invariant inside arbitrary legacy media objects.

The UI-owned composer record is itself nested inside a byte field. Its framing is checked separately when a snapshot is created/read, and Pocket restore uses an opt-in validated Engine decoder for its Codable shape. Native regressions for malformed inner bytes and a real `ChatInterfaceState` round trip passed in the `d02b731` Mac run.

Age/size cleanup, explicit cache removal and destructive MediaBox moves respect durable pins. Writable cache paths stay unchanged. Complete/ranged reads can resolve the retained copy, including callbacks from existing file contexts. Startup verifies and restores originals before pending uploads; failed recovery pauses affected marked messages, while unrelated messages remain eligible. The Pocket exposes a recovery notice. Collection releases archives only after their final durable owner disappears; failed local messages retain ownership.

Startup first performs the original database/error/upgrade checks on `Postbox.sharedQueue`. After those transactions finish, MediaBox recovery runs off that queue; the initialized instance is then injected and Postbox is published back on its queue. A queue-bound holder keeps SQLite's lifetime on the correct queue during the transition. A collector may hold the retention lease while waiting for a Postbox transaction, so acquiring that lease on the same queue creates a deadlock. This ordering keeps blocking recovery and its failure flags, preserves the original invalid-database `.error` path, and prevents uploads before recovery. The held-lease cold-reopen regression passed with the earlier off-queue ordering in `d02b731`. The latest SQL-first ordering and its two invalid read-only layout checks at `25a3961` still require a Mac run; 114 portable tests and reconstruction passed on Linux.

The canonical composer send path stores a recovery snapshot before clear-on-history hooks, Send When Online completion and automatic forum-topic transfer. A local-only attribute carries its operation through media transformation; the normal enqueue transaction claims pending-message ownership. A consumed operation cannot be reused as a new send. Retry must identify actual source messages and preserve them if replacement cannot be prepared. Unsupported mixed ephemeral/normal splits are refused before message mutation, leaving recovery intact. Pocket ownership creates no upload subscription or delivery acknowledgement.

Interrupted sends appear separately in the Pocket. Explicit recovery moves the snapshot to a card without overwriting current input and observes the 20-card limit. At capacity, recovery remains available until a slot is freed. Recovery entries are separately bounded and never silently evicted.

## Scope and remaining validation

- Traversal includes canonical nested media, file/image representations, video covers, alternatives, thumbnails and local custom-emoji files. Complete bytes are required; preparation does not download missing media.
- Pre-send ownership protection covers `sendCurrentMessage`, including rich/expanded composer sends. Delayed clear callbacks for canonical sends, stickers, bot results and bot commands now compare the captured canonical input, scope and reply context. Successful Pocket transfers also advance a generation counter, so restoring an identical card invalidates an older clear callback. These guards preserve newer input; they do not add picker-only media to Pocket ownership. Interaction QA remains pending.
- The passing `d02b731` cases use actual bytes, MediaBox reads/eviction and Postbox reopen/transactions: temporary local-file references after source deletion, force cleanup, age/size candidates, shared cards and swap at capacity, Delete/Undo/finalize, pre-send recovery, failed messages, explicit retry and final-owner release. Corrupt-metadata isolation and duplicate-send rejection also passed.
- The latest SQL-first startup change remains unrun on a Mac. Process-kill/fault injection, account switching with media, successful network-send migration, all representation variants, existing reader races and low-disk behavior require further acceptance evidence. No live account or network delivery is used in the fixture. Hosted composer tests and the full-client story also remain incomplete; no video was produced.

Relevant modules are Postbox's MediaBox/TimeBasedCleanup, TelegramCore's ownership/prepared-send helpers, Account/EnqueueMessage, canonical ChatInterfaceState autosave and the production composer UI. This integrates existing storage and upload paths; it does not replace them.
